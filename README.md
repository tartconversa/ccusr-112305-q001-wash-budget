# 雪具洗护站 · 用水配额与交接核算

一个**仅依赖 Python 3.11 标准库**的核算项目，处理洗护批、操作记录、进出水表、
混洗料筐、回用罐、取样检测、跨站调拨与已确认领件时间。

目标不是给出一堆看似精确的平均数，而是：

- 能确定的给精确值，不能确定的给**区间 + 原因 + 证据编号**；
- 换表、缺测、共享冲洗、迟报错日**绝不强行相减或按数量平摊**；
- 检测版本订正、跨站调拨、表底更正都按**事件身份与版本**处理；
- 已确认交接是沉淀事实，任何重算排程都不能覆盖；
- 配额占用、可放行水、应计水量、未结算差额能追到**同一批 / 同一领件承诺**。

## 运行

在项目根目录 `/workspace` 下：

```sh
# 原有资料契约测试 + 本项目全部规则测试
python3 -m unittest discover -s tests

# 查看原始资料概要（原有脚本）
python3 scripts/inspect_sources.py

# 生成完整 JSON + Markdown 核算报告到 reports/
python3 scripts/station_report.py
# 等价方式
python3 -m washstation write reports

# 常用查询（均输出 JSON）
python3 -m washstation availability     # 新班还有几升新水可用
python3 -m washstation scenarios        # 合洗/延迟/回用水情景比较
python3 -m washstation anomalies        # 水表冲突/迟报/换表
python3 -m washstation shift            # 下一班交接归因 -> 取件承诺
python3 -m washstation billing          # 柜台计量单是否补发/补收
python3 -m washstation day 2026-04-11   # 当日水量归属
python3 -m washstation reconcile C141   # 单批四方核对
python3 -m washstation markdown         # 站长可读摘要（stdout）
```

作为库使用：

```python
from washstation import Station

st = Station()                       # 默认读取 ./data
st.new_shift_availability()          # 新班新水口径
st.scenarios()                        # 次日领件情景
st.overturn("T13")                    # 检测推翻级联
st.transfer("TX1")                    # 跨站调拨计量差
st.tank_positions()                  # 罐段等级/合规可用量/预留
st.billing_actions()                  # 计量单补发/补收
st.reconcile_cycle("C141")           # 配额/放行水/应计/差额
st.shift_log()                        # 下一班异常归因与承诺追踪
st.verify_leases([("青崖", 20)])      # 租赁可发量承诺核验
```

| `washstation/reconcile.py` | 同一批的配额占用/放行水/应计/未结算差额、配额—可交付核对 |

## 这批资料的关键结论（可由测试与报告复算）

当前时点取 **2026-04-12 slot0**（物业已切新经营日，只有该时段有配额行 14 L、
机器 A、件数容量 12，`carry_from=2026-04-11`）。

### 1. 新班新水：配额 14 L，但只能谨慎按 1 L 安排

- 04-12 当天**没有新水实测表链**，读表缺口不能当作有水：`certified_available=null`。
- `NE10/NE11`（盖日 2026-04-05）表码数值上恰好接在 04-11 表尾 `M1330=3160` 之后：
  `M1330→NE10 +2 L`（表底差，归前一日）、`NE10→NE11 +13 L`（段内差分）。
  但盖日与累计顺序冲突（`NE11=3175 → M1300=3100` 倒退 75 L），只能列为
  **计量不可判定 / 迟报候选**。
- 因此给出三个不同口径，绝不合并成一个精确数：
  - 配额上限 `14 L`；硬占用 0 时可安排上限 `14 L`；
  - 把 13 L 候选段视作占用准备后的**谨慎区间 `1–14 L`，核实前按下限 1 L**；
  - 认证可用量 `null`（无当前班实测背书）。
- `+2 L` 表底差对应 `UT1 12→14` 的订正，只引起 **04-11 补收 ≈0.0122 元**
  （2 L × 6.1 元/m³），**不增加** 04-12 配额。

### 2. 计量归属：总量对得平，缺口有原因

- 04-11 new-a 实测 `3100→3160 = 60 L`：slot0/1/2 差分 19/20/21。
  - slot1=20 → C141（东柜 B140 + 西柜 B141 合洗）；
  - slot2=21 → C142（团课 B142 单洗）；
  - slot0=19 无洗护批 → **未归属**（预注水/管路/记录缺失）。
  - 已归属 41 + 未归属 19 = 60，守恒。
- 回用水表 04-11 走字 21 L，批记录 `reused_l` 合计 3 L，差额 18 L
  列为未归属回用水（未登记冲洗/罐操作）。
- 换表日 01-24（new-a→new-b）总量只能给 **37–59 L**，03-21 为 **33–55 L**：
  换表边界 slot2→3 不能相减，上界按该时段配额 22 L 保守封项。
- 东/西柜共享 C141 且无柜台分表：柜台实际量各给 `[0,20] L` 区间，
  **不做数量平摊**；按件数比例的 11/10 分摊仅作“估算参考”并带误差警告。
- `individual` 独立支路只在 11 个日子有实测（01-31、03-14、04-11 全天 null）。
  用有实测日拟合 `individual ≈ 14.42 + 0.143×件数`，MAE≈1.96 L；
  主表模型 MAE≈3.45 L。报告按**季节 5 周相位、03-07 常用→节水的程序更新、
  件数批量差异**解释残差，不把共线变化全部记为节水效果。

### 3. T13 被撤销：三件事同时重判，缺口 19 件

T13 v1（slot2，许可 `["普通"]`，通过）被 v2（slot4，`撤销`，`allowed_use=[]`）推翻，
关联 C131 / B130 / B131：

- **未用回用水**：许可清空，同范围水冻结/降级，不能再据此省新水；
- **已洗料筐**：B130 计划“处理中”→ 暂停放行；B131“未开洗”→ 尚可调整；
  未拿到已交接回单前都不可发；
- **领件缺口**：R130/R131（slot5/6）共 **2 篮 19 件**。
  若 slot4 才发现、重洗需 2 段，B130 赶不上 slot5（9 件需替换件），
  B131 最早 slot6 可赶在 slot6 截止前重洗。
- 已交接的 B121（pickup 回单）等事实固定，重算不得覆盖。

### 4. 罐与跨站调拨：有水不等于许可可用

- TX1（松谷 A-9 → 青崖，Q42）：提议/出站 11，首报到站 9，到站更正为 **10**；
  最新两端计量差 **1 L** 挂账待查。出站后松谷 A-9 15 L 中 **11 L 已离开、
  仅剩 4 L 可安排**；到站确认前青崖按不可用看。
- 到站 9 L 入 B-2（台账 `配入 9, parent=A-9`），与 U-8 的 8 L 待测水混合成
  `混合 17 L（grade=待测）`。按到站更正 9→10，B-2 订正为 **18 L**。
- 混合后整段 **待测**，原 A-9 的“普通”等级不能独立批准出罐：
  B-2 `certified_usable=0`，尽管实物有 18 L。H2(B141)、H3(B142) 与
  TX2/Q43 的 6 L 争用预留**全部**重新判断：扣 6 L 后实物余量 12 L，
  合规余量却是 −6 L。

## 设计原则

1. **区间优先**：`Range(lo, hi=None)` 贯穿计量、需求、占用与金额；
   不确定归属绝不塌缩为点估计。
2. **事件身份与版本**：调拨按 `transfer+event` 区分两端申报，检测/单据按
   `check/statement + version` 保留订正轨迹，最新版才是当前有效结论。
3. **证据可追溯**：每条结论带 day/slot、reading/event/check/cycle/basket id 与原因码。
4. **事实不可变**：已交接以柜台回单为准，重算只能新建方案，不能改写沉淀事实。
5. **标准库、无 IO 副作用**：核算函数不修改 `data/`；报告只写入显式指定的输出目录。
